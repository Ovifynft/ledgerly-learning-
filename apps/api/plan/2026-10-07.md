# Ledgerly Code Task Plan - 2026-10-07

## Goal

Introduce Ledgerly's first financial operation by adding transaction records and authenticated account deposits.

By the end of this phase, an authenticated user should be able to deposit money into an account they own, have the account balance updated, and have a permanent transaction record created for that financial operation.

The balance update and transaction record must succeed or fail together through a database transaction.

Withdrawals, account-to-account transfers, idempotency, concurrent balance protection, ledger entries, payment providers, and webhooks remain future work.

## Atomicity Tasks

- [ ] Perform the balance update and transaction creation inside a Prisma database transaction.
- [ ] Ensure the balance is not updated if transaction-record creation fails.
- [ ] Ensure a transaction record is not committed if the balance update fails.
- [ ] Keep the financial operation's database changes inside the same transaction boundary.

Conceptually, the operation should behave as one unit:

```text
Deposit Request
      |
      v
Database Transaction Begins
      |
      +--> Update Account Balance
      |
      +--> Create Transaction Record
      |
      v
Both Successful?
   /       \
 YES       NO
  |         |
Commit    Rollback
```
