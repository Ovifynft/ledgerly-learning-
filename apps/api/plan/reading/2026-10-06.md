# Ledgerly Learning Plan - 2026-10-06

## Goal

Understand the authentication and authorization concepts required to implement today's Ledgerly authentication slice without blindly copying an authentication tutorial.

By the end of the phase, you should be able to explain how Ledgerly moves from:

```text
Email + Password
      ↓
Authentication
      ↓
JWT
      ↓
Authenticated Request
      ↓
Current User
      ↓
Authorization / Account Ownership
```

The goal is understanding, not memorizing documentation.

```json

```

# Learning Block 4 — JWT Fundamentals

## Read

### JWT Introduction

https://www.jwt.io/introduction

## Learn

- [ ] What a JWT is.
- [ ] Header.
- [ ] Payload.
- [ ] Signature.
- [ ] Claims.
- [ ] The `sub` claim.
- [ ] The `exp` claim.
- [ ] Signing.
- [ ] Verification.
- [ ] Encoding vs encryption.

Understand:

```text
xxxxx.yyyyy.zzzzz

  |     |     |
  |     |     └── Signature
  |     |
  |     └──────── Payload
  |
  └────────────── Header
```

A JWT payload is not inherently secret.

For example:

```json
{
  "sub": 12,
  "email": "ada@example.com"
}
```

can be inspected by someone possessing the token.

Therefore this would be inappropriate:

```json
{
  "sub": 12,
  "password": "secret123"
}
```

## You Should Be Able To Explain

- [ ] What are the three parts of a JWT?
- [ ] Is the JWT payload encrypted?
- [ ] What does signing a JWT accomplish?
- [ ] What does `sub` mean?
- [ ] Why shouldn't sensitive information be stored in the payload?
- [ ] What happens if someone modifies the payload?
- [ ] Why do access tokens expire?
- [ ] If someone steals a valid JWT, what can they potentially do until it expires?

## Understand


## Learn
