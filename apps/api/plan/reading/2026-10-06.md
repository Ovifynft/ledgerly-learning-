## Reading List

The goal of this reading list is not to read every page of the NestJS or JWT documentation.

Read enough to understand the concepts required for today's implementation, then return to the documentation when the implementation exposes something you do not understand.

### 1. Authentication vs Authorization

Understand these concepts before writing authentication code.

Read:

- MDN — HTTP Authentication  
  https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Authentication

- Auth0 — Authentication vs Authorization  
  https://auth0.com/docs/get-started/identity-fundamentals/authentication-and-authorization

Focus on:

- What authentication means.
- What authorization means.
- Credentials vs identity.
- Why knowing a user's ID is not proof of identity.
- Why an authenticated user can still be unauthorized to access a resource.
- `401 Unauthorized` vs `403 Forbidden`.

You should be able to explain:

```text
Authentication:
"Who are you?"

Authorization:
"Are you allowed to do this?"
```

---

### 2. Password Storage And Hashing

Understand password storage before implementing registration.

Read:

- OWASP Password Storage Cheat Sheet  
  https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html

Focus on:

- Why passwords should not be stored as plain text.
- Hashing vs encryption.
- What a salt is.
- Why passwords require deliberately slow password-hashing algorithms.
- Why general-purpose hashes such as SHA-256 are not appropriate by themselves for password storage.
- Modern password-hashing algorithms such as Argon2id and bcrypt.

Do not try to memorize every OWASP recommendation.

You should be able to explain this flow:

```text
Registration

Password
   |
   v
Password hashing algorithm
   |
   v
Password hash
   |
   v
Database
```

And:

```text
Login

Submitted password
       |
       v
Password verification
       |
       +---- Stored password hash
       |
       v
Match / No Match
```

### 4. JWT Fundamentals

Read:

- JWT Introduction  
  https://www.jwt.io/introduction

Focus on:

- What a JWT is.
- Header.
- Payload.
- Signature.
- Claims.
- `sub`.
- Expiration (`exp`).
- Signing and verification.
- Why JWT payloads should not contain secrets.

Understand the basic structure:

```text
xxxxx.yyyyy.zzzzz

  |     |     |
  |     |     └── Signature
  |     |
  |     └──────── Payload
  |
  └────────────── Header
```

Important:

A JWT payload is normally encoded, not encrypted.

Someone possessing a JWT can generally inspect its payload.

The signature exists primarily so the server can detect modification and verify that the token was issued by a trusted signer.

You should be able to explain why this is reasonable:

```json
{
  "sub": 12,
  "email": "ada@example.com"
}
```

but this is not:

```json
{
  "sub": 12,
  "password": "secret123"
}
```

### 5. NestJS Guards

Read:

- NestJS Guards  
  https://docs.nestjs.com/guards

Focus on:

- What a guard is.
- `CanActivate`.
- `ExecutionContext`.
- Where guards sit in the request lifecycle.
- Route-level guards.
- Controller-level guards.
- Global guards.
- How a guard decides whether a request continues.

Understand the conceptual flow:

```text
HTTP Request
      |
      v
Middleware
      |
      v
Guard
      |
      v
Interceptor / Pipe / Controller flow
      |
      v
Controller
```

For Ledgerly, think:

```text
GET /accounts
      |
      v
Authentication Guard
      |
      +--- Invalid JWT ---> 401
      |
      v
Authenticated user
      |
      v
AccountsController
```

You should understand why the controller does not need to manually write:

```text
if token is invalid...
```

inside every endpoint.

### 8. NestJS Configuration

Read:

- NestJS Configuration  
  https://docs.nestjs.com/techniques/configuration

Focus on:

- Environment variables.
- `ConfigModule`.
- `ConfigService`.
- Keeping secrets outside source code.

For example, understand why this is undesirable:

```ts
secret: 'ledgerly-super-secret-key'
```

inside committed application code.

Instead, configuration should eventually come from something such as:

```text
JWT_SECRET=...
```

Do not commit real secrets to Git.

### 9. Authorization And Resource Ownership

Read:

- NestJS Authorization  
  https://docs.nestjs.com/security/authorization

Do not implement the full roles/permissions system from this documentation today.

Focus on the underlying idea:

```text
Authenticated
      !=
Authorized for every resource
```

Relate it directly to Ledgerly.

Example:

```text
JWT says:

userId = 7

Request:

GET /accounts/20

Database:

Account 20
userId = 12
```

User 7 is authenticated but should not be authorized to access Account 20.

Today's authorization requirement is primarily resource ownership rather than a complex RBAC system.

### 10. HTTP Bearer Authentication

- Why protected endpoints expect this header.

## Reading Completion Criteria

You do not need to memorize the documentation.

The reading is complete when you can explain, without looking at the documentation:

- [ ] Authentication vs authorization.
- [ ] Hashing vs encryption.
- [ ] Why Ledgerly stores `passwordHash` instead of `password`.
- [ ] How password verification works without recovering the original password.
- [ ] What a JWT is.
- [ ] Header vs payload vs signature.
- [ ] Why JWT payloads are not secret.
- [ ] What `sub` means.
- [ ] How a JWT is signed and later verified.
- [ ] Why access tokens expire.
- [ ] What a NestJS guard does.
- [ ] Where the guard sits in the request lifecycle.
- [ ] How `/auth/me` knows which user is making the request.
- [ ] Why `POST /accounts` no longer needs `userId`.
- [ ] How Ledgerly prevents User A from reading User B's account.
- [ ] The difference between `400`, `401`, `403`, and `404` in today's API.
